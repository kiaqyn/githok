# GitHok

像刷短视频一样发现 GitHub：一次认识一个开源项目，划走继续，喜欢就收藏。

## iPhone 与线上版本

项目提供 Sites 私人部署，部署完成后可在 iPhone Safari 中通过 HTTPS 网址访问，用创建该站点的 ChatGPT 账号登录。不需要让手机连接电脑的本地端口；`127.0.0.1` 仅适用于运行服务的电脑本身。

线上入口由 Sites 返回的部署结果确定，部署状态记录在本地 `outputs/phone-deployment.json`。线上使用同一套检索逻辑和前端，通过 Cloudflare Worker 运行，使用边缘缓存。默认公开项目列表随构建保存一份带时间戳的真实快照，仅在上游失败时作为明确标注的历史缓存回退，超过七天不再使用。

构建线上版本：`npm install` 后运行 `npm run build`，需要 `.openai/hosting.json` 中已注册的站点 ID。普通本地运行仍然无需安装依赖。

## 打开

需要 Node.js 22 或更高版本，无需安装依赖。Windows 双击 **start-githok.cmd**，或在本目录运行：

```powershell
node server.mjs
```

浏览器打开 **http://127.0.0.1:4317**。关闭运行窗口或按 Ctrl+C 停止服务。若端口冲突，可先设置 `$env:PORT='4318'` 再运行。

## 已有功能

- 实时读取 GitHub 公开仓库：项目介绍、星标、Fork、语言、topic、许可证和更新时间。
- 鼠标滚轮、手机上下滑动、键盘 ↑ / ↓ / J / K / 空格切换项目；B 收藏；R 读 README；/ 搜索。
- 六种兴趣分类；热门精选、最近上新、小众宝藏三种发现方式；项目搜索、分页加载。
- 收藏与浏览足迹保存在当前浏览器；收藏不会修改 GitHub 星标；浏览足迹保留最近 200 项，收藏上限 300 项。
- 详情展示原作者 README 的安全文字预览，以及原仓库和项目网站链接。
- 手机、平板和桌面布局；键盘操作、对话框焦点与减弱动画设置。

## 数据依据

从官方 GitHub REST API 获取公开元数据，不使用模拟项目。介绍保留原文，卡片封面由本应用根据项目名称生成，不是项目截图或运行效果。

- **热门精选**：近 180 天有更新、总星标超过 1,000。
- **最近上新**：近 90 天创建、总星标超过 10。
- **小众宝藏**：近 180 天有更新、总星标在 50–5,000 之间。
- 各模式按总星标降序；这不是 GitHub Trending 日涨幅榜，也还没有训练个人推荐模型。
- 兴趣分类根据仓库作者填写的 topic 筛选；搜索按字面短语匹配名称、描述与 topic，按 GitHub 相关度排序、不限星标数，保留所选兴趣分类。

GitHub 数据缓存 15 分钟，每个分页独立缓存，重复请求合并。网络或限流错误发生时，可读取不超过 7 天的旧缓存，页面明确标出历史缓存时间。缓存仅包含公开项目数据，存放于 `.cache/cache.json`，最多 80 个条目。遇到限流后按照响应头暂停对应接口请求，不自动循环重试。

README API 限流或暂时不可达时，仅补查一次该公开仓库的 `HEAD/README.md` 原始文件；不转发 API 凭据，仍限制文字长度并缓存。若仓库使用其他文件名且 API 不可用，页面保留明确错误和 GitHub 原文链接。

公开接口有访问频率限制，详见 [GitHub 官方说明](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)。日常大量使用时，可由你自行设置仅用于公开数据的 `GITHOK_GITHUB_TOKEN` 环境变量；不要把凭据写进前端或提交到仓库。本版本无需凭据即可启动。

```powershell
node --test
```

测试覆盖参数与路径校验、并发请求合并、缓存过期与离线回退、限流暂停、README 长度边界和 HTTP 路由。真实接口与页面交互验收记录见 `verification.md`。

## 当前边界

这是可在本机使用的 0.1 版。收藏暂不跨设备同步，尚无账户与 GitHub OAuth，不会自动生成中文摘要；按兴趣发现来自 topic 筛选。规模化部署前还需要服务端用户隔离、共享缓存和 API 配额规划。
