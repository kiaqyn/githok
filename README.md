# GitHok

像刷短视频一样发现 GitHub：一次认识一个开源项目，划走继续，喜欢就收藏。

## iPhone 与线上版本

线上演示：[打开 GitHok](https://githok-jiao.qynily.chatgpt.site)。网站已公开，可在 iPhone Safari 或桌面浏览器中直接访问，无需登录 ChatGPT。不需要让手机连接电脑的本地端口；`127.0.0.1` 仅适用于运行服务的电脑本身。

线上入口由 Sites 返回的部署结果确定，部署状态记录在本地 `outputs/phone-deployment.json`。线上使用同一套检索逻辑和前端，通过 Cloudflare Worker 运行，使用边缘缓存。默认公开项目列表随构建保存一份带时间戳的真实快照，仅在上游失败时作为明确标注的历史缓存回退，超过七天不再使用。

构建线上版本：`npm install` 后运行 `npm run build`，需要 `.openai/hosting.json` 中已注册的站点 ID。普通本地运行仍然无需安装依赖。

## 打开

需要 Node.js 22 或更高版本，无需安装依赖。Windows 双击 **start-githok.cmd**，或在本目录运行：

```powershell
node server.mjs
```

如需临时启用中文简介与速览，可双击 **start-githok-ai.cmd**（或运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\start-githok-ai.ps1`），按提示隐藏输入凭据与模型配置；密钥只留在当前运行进程内存中，不会保存进任何文件。

浏览器打开 **http://127.0.0.1:4317**。关闭运行窗口或按 Ctrl+C 停止服务。若端口冲突，可先设置 `$env:PORT='4318'` 再运行。

## 产品介绍短片

[promo/githok-keynote.html](promo/githok-keynote.html) 是约 48 秒的单文件 HTML 产品短片，内嵌字体、品牌图片和真实网页截图，可离线打开。包含播放、暂停、拖动进度、全屏与静音控制，配乐由 Web Audio 在本地生成，不依赖外部模型接口。MP4 导出文件保存在本地 outputs 目录，不提交到源码仓库。

线上目前支持发现、筛选搜索、README 原文、本地收藏和浏览足迹。AI 中文生成服务和云端 GitHub 登录／真实 Star 尚未启用，界面会明确提示。中文速览请求有 30 秒的前端等待上限；超时保留原文，且不会自动循环调用收费服务。

## 已有功能

- 实时读取 GitHub 公开仓库：项目介绍、星标、Fork、语言、topic、许可证和更新时间。
- 鼠标滚轮、手机上下滑动、键盘 ↑ / ↓ / J / K / 空格切换项目；B 收藏；R 读 README；/ 搜索。
- 六种兴趣分类；热门精选、最近上新、小众宝藏三种发现方式；项目搜索、游标续载。
- 自动保存当前发现流的项目位置、筛选、搜索、已加载项目与续载游标；同一浏览器再次打开或刷新时，可接着最近 24 小时内保存的进度看，无需先重查首页。恢复内容标成“本地浏览进度”，工具栏的刷新按钮可从头取新推荐，收藏保留。
- 网络或限流导致续载暂停时，保留已有项目并显示常驻重试入口；限流倒计时结束后可手动重试。网络恢复不会自动循环发请求。断网浏览适用于已打开页面中的已加载项目，打开网站本身仍需可用静态资源。
- 收藏与浏览足迹保存在当前浏览器；收藏不会修改 GitHub 星标；浏览足迹保留最近 200 项，收藏上限 300 项。
- 收藏与足迹默认显示细线分隔的项目列表；点击条目进入逐个浏览，也能随时返回列表。两种布局都支持本地搜索，搜索无结果时可直接清空，不会丢失收藏。
- 手机支持系统原生分享；浏览器不支持或分享失败时尝试复制链接，再不可用时提供可手动复制的链接。主动取消系统分享不会额外复制。不会自动向联系人发送消息。
- 信息流增加浏览进度条，采用浅色编辑式布局、开放的大字号项目排版和横向导航；收藏列表与阅读面板遵循同一套设计，手机列表独立滚动，逐个浏览时保留上下滑动，并忽略取消及多指手势。
- 详情展示原作者 README 的安全文字预览，以及原仓库和项目网站链接。
- 手机、平板和桌面布局；键盘操作、对话框焦点与减弱动画设置。
- 右上角提供中文 / English 切换，默认跟随浏览器支持的语言，手动选择保存在当前浏览器。切换保留当前项目、搜索输入和收藏；导航、筛选、日期、错误提示与说明均双语。启用摘要服务后，中文模式可切换“中文速览 / 中文简介 / 作者原文”；README 阅读仍保留作者原文。

## 双击 Star 与 GitHub 登录

双击项目展示区或点击星形 **Star** 按钮，会为登录的 GitHub 账号添加真实 Star。重复双击不会取消 Star；本地书签收藏仍独立。链接、按钮、选中文字、长按、拖动及多指手势不触发；成功动画只在 GitHub 返回成功后播放。失败可手动重试，不会自动循环写入。已划走项目的响应不会给新项目亮星。

目前登录后端限于本地 Node 服务，账号令牌仅存服务进程内存，最多 8 小时；重启或断开连接即丢弃本地会话。退出连接不等于撤销 GitHub 上的应用授权，可在 GitHub 设置中撤销。令牌不写进浏览器存储、项目文件或日志。

部署者需在 GitHub Settings → Developer settings → OAuth Apps 创建自己的应用。默认本地 Homepage URL 为 `http://127.0.0.1:4317`，Authorization callback URL 为 `http://127.0.0.1:4317/api/github/callback`。仅在服务进程环境中提供 `GITHOK_GITHUB_CLIENT_ID` 与 `GITHOK_GITHUB_CLIENT_SECRET`。变更端口或域名时，同时将 `GITHOK_PUBLIC_ORIGIN` 设置为精确的访问来源，并更新 GitHub 回调地址；公网必须 HTTPS。不要把 Secret 发进聊天或提交仓库。

采用官方 OAuth 网页授权、随机 state 与 PKCE，授权范围 `public_repo`。这个 OAuth 范围包含比 Star 更广的公开仓库写权限，授权页会显示；服务只提供公开仓库添加 Star 的入口，不提供代码写入或取消 Star。应用未配置时界面明确提示，普通推荐和本地收藏继续可用。现有无持久会话存储的云端 Worker 不启用账号写操作，不能靠实例内存冒充跨实例登录。

协议依据：[GitHub OAuth 网页授权](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps#web-application-flow)、[GitHub Star API](https://docs.github.com/en/rest/activity/starring#star-a-repository-for-the-authenticated-user)。真实账号授权及添加 Star 需要完成应用配置后由用户验证；合成协议测试不能代替这一步。

## 数据依据

从官方 GitHub REST API 获取公开元数据，不使用模拟项目。作者原文可随时查看；中文简介和速览明确标注为 AI 整理，并注明依据作者简介还是 README 节选。项目名称、星标、语言与标签仍来自原始数据。银蓝雕塑是应用的品牌装饰，并非项目截图或运行效果。

## 中文简介与速览

这是可选的服务端功能。不配置文字服务也能正常浏览、收藏和阅读原文；界面会明确提示中文速览尚未启用。需要提供支持非流式 Responses JSON 的文字接口，以及该接口实际支持的模型。

仅在服务端进程环境配置 `GITHOK_AI_BASE_URL`、`GITHOK_AI_KEY`、`GITHOK_AI_MODEL`。服务地址必须使用 HTTPS（本机回环地址可使用 HTTP）。凭据不会打包到页面或构建产物，不要写进前端、仓库或日志。本地服务重启后，需重新提供进程环境中的配置；项目不会代为持久保存密钥。

- 中文模式在项目停留约 650 毫秒后才请求；快速划过、页面隐藏和英文模式不会提前批量生成。中文简介与速览共用一次生成，切换视图不另收费。
- 优先使用推荐流已获取的公开简介。没有简介时才读取有界 README 节选；资料不足便保留原文提示，不补写未经说明的功能或适用人群。
- 浏览器最多保留 80 条生成结果，本地服务最多保留 250 条派生缓存，最长 30 天；源简介、标签或语言改变会产生新的内容指纹。缓存命中次数不等于已核算的账单节省。
- 默认每小时最多 60 次新的生成尝试，可用 `GITHOK_BRIEFS_PER_HOUR` 调整到 1–300。该限制只针对一个服务进程或 Worker 实例，不是跨实例的全局费用硬上限；多用户部署还需要共享配额和持久缓存方案。
- 同时只生成一个项目，失败后不会自动反复调用。错误、限流、返回内容不完整或资料更新时，原文仍可阅读，用户可以手动重试。生成文本只作为文字渲染，不执行其中的 HTML、脚本或命令。
- AI 整理可能出错，作者原文始终是核对依据；“适合谁”仅在资料明确给出对象时显示。不会整篇翻译 README，也不会用 AI 改写仓库名称、代码、许可证或星标数。

- **热门精选**：近 180 天有更新、总星标超过 1,000。
- **最近上新**：近 90 天创建、总星标超过 10。
- **小众宝藏**：近 180 天有更新、总星标在 50–5,000 之间。
- 连续发现按创建年份从新到旧探索，每个时间段内按总星标降序；若某段结果太多，会自动拆成更小的时间段。搜索时段内按 GitHub 相关度排序。这不是全站总星标榜或 GitHub Trending 日涨幅榜，也还没有训练个人推荐模型。
- 兴趣分类根据仓库作者填写的 topic 筛选；搜索按字面短语匹配名称、描述与 topic，时间段内按 GitHub 相关度排序、不限星标数，保留所选兴趣分类。

连续信息流每批 30 项，在当前批还剩 5 项时预取后续批次；前端跨批去重，不把已加载数量当作全部库存。没有 30/300 项的浏览总上限。GitHub 单次搜索最多返回 1,000 项，本应用将创建时间范围拆分到不超过 990 项后分页，接续其他不重叠时间范围。游标固定筛选和时间基准（每 15 分钟一个基准），换筛选会创建新流。极端情况下同一秒内匹配超过 990 项，或 GitHub 返回不完整结果时，仍会有明确的结果不完整提示，不声称穷尽全站。接口保留旧的有界 page 参数供兼容，页面实际使用 stream=1 和 nextCursor。

通常保留最近 300 条完整推荐数据供回看；若预取期间回翻，可能临时多保留一批，最多 330 条。已发现的数字 ID 用于本次去重，这不会阻止继续加载新项目。本地进度使用 `githok:resume:v1`，短暂停留 350 毫秒后合并写入，并在页面隐藏时保存，大小上限 1,000,000 字符；损坏、过期或不一致的进度会安全忽略。存储失败时显示进度未保存，收藏和足迹使用独立的存储键。进度随浏览器保存，不跨设备同步。

空时间段每次最多查 4 个请求，前端每次最多接续 3 批，仍无结果时保留“继续寻找”，限流期间不自动重试。预取不阻塞已有项目切换，也不重置正在阅读的长文滚动位置。

GitHub 数据缓存 15 分钟，每个分页独立缓存，重复请求合并。网络或限流错误发生时，可读取不超过 7 天的旧缓存，页面明确标出历史缓存时间。缓存仅包含公开项目数据，存放于 `.cache/cache.json`，最多 80 个条目。遇到限流后按照响应头暂停对应接口请求，不自动循环重试。

README API 限流或暂时不可达时，仅补查一次该公开仓库的 `HEAD/README.md` 原始文件；不转发 API 凭据，仍限制文字长度并缓存。若仓库使用其他文件名且 API 不可用，页面保留明确错误和 GitHub 原文链接。

公开接口有访问频率限制，详见 [GitHub 官方说明](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)。日常大量使用时，可由你自行设置仅用于公开数据的 `GITHOK_GITHUB_TOKEN` 环境变量；不要把凭据写进前端或提交到仓库。本版本无需凭据即可启动。

## 当前边界

这是可在本机使用的 0.1 版。收藏暂不跨设备同步，尚无账户与 GitHub OAuth；按兴趣发现来自 topic 筛选。中文简介与速览需要额外配置并使用文字服务，不代表对全部项目做过人工核验。规模化部署前还需要服务端用户隔离、共享缓存和 API 配额规划。
